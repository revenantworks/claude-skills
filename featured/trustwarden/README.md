# trustwarden

**Vet it before it runs.** A one-skill plugin: `revenantworks-warden-trustwarden` from the warden
pack, version 1.0.0.

```
/plugin marketplace add revenantworks/claude-skills
/plugin install trustwarden@revenantworks
```

## What it does

trustwarden vets third-party skills, plugins, MCP servers and GitHub Actions before they are
installed, and ends with a verdict (PASS, CONDITIONAL, HOLD or FAIL) and the terms to install under,
never a bare score. It never installs or runs the candidate.

## Why it is different

- Scanners skip files without saying so. trustwarden lists every file with the readers that read it;
  an unread executable, archive or oversized file means the verdict cannot be PASS.
- PASS also needs a second scanner to agree.
- Its terms are tied to Claude Code's own controls: the commit SHA to pin, auto-update off, and the
  exact rules to add.

## Try it

- *"Is this skill safe to install?"*
- *"Vet this MCP server before I add it."*
- *"A plugin update came in, what changed?"*

**Needs:** Python 3 and git. It drives skillspector, zizmor, pinact and OpenSSF Scorecard when
present; every scanner is optional and owner-installed.

> [!IMPORTANT]
> **Install this plugin or the warden pack, not both.** Both carry the same skill name; the listing
> pays for the description twice, and an update to one copy leaves two bodies under one name. In the
> pack, gatewarden writes the rules trustwarden names.

Everything under `skills/` is generated by `tools/build.py` from the pack source; edit the pack
source, never this copy. Apache-2.0; the skill folder carries `LICENSE` and `NOTICE`.
