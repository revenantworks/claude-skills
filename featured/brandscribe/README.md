# brandscribe

**One brand definition, everywhere Claude builds.** A one-skill plugin:
`revenantworks-scribe-brandscribe` from the scribe pack, version 1.0.0.

```
/plugin marketplace add revenantworks/claude-skills
/plugin install brandscribe@revenantworks
```

## What it does

brandscribe keeps your brand definitions in plain files, several side by side, and turns the one
you pick into what Claude and people build with. It builds a **Claude Design System**: the design
system artifact that Claude's slides, documents and designs on claude.ai build with. It also
writes a repo's `DESIGN.md` and `VOICE.md`, a voice profile, an agent brief and a one-file brand
guide. It ships with no brand: nothing exists until you build one or hand one in.

## Why it is different

- **Built for Claude Design.** It reads the live Design System type's own instructions first, then
  builds the system from your written definition: tokens, brand book, fonts and marks. A deck or
  design made on claude.ai picks the brand up from there.
- **Re-sync without losing edits.** When the brand changes, it compares the live system with the
  definition in four lists (matched, changed, live-only, definition-only) and changes only what the
  definition changed. Edits made on the system's pages stay.
- **The voice travels with the look.** The brand book carries the voice profile, with before and
  after pairs and banned phrases, so slides and agents that read the system also get the voice.
- **A UI check for any built page,** with or without a brand: 31 rules for contrast, labels, focus,
  missing fonts and generic-looking UI, then a scored review.

## Try it

- *"Turn this style guide into a Claude Design System."*
- *"The brand colours changed, re-sync the design system."*
- *"Check this built page before it ships."*

**Needs:** nothing to work. The Artifact tool's Design System type makes the live system; without
it every deliverable comes back as files. Two optional Python checkers use only Python's built-in
library, so there is nothing to install.

> [!IMPORTANT]
> **Install this plugin or the scribe pack, not both.** Both carry the same skill name; the listing
> pays for the description twice, and an update to one copy leaves two bodies under one name.

Everything under `skills/` is generated by `tools/build.py` from the pack source; edit the pack
source, never this copy. Apache-2.0; the skill folder carries `LICENSE` and `NOTICE`.
