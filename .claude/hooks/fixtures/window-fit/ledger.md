## Design decided by the controller after U1 (2026-09-17)

- Data source: the statusLine JSON (`rate_limits.five_hour` / `seven_day`, `used_percentage` + `resets_at`, Max plans, after the first API response) — verified in code.claude.com/docs/en/statusline.md; the hooks reference carries NO rate_limits field (verified), so the guide agent overstated that half. No per-model window exists in the data; the Fable window is owner-entered.
- Mechanism: a rig statusline script writes `~/.claude/usage-windows.json` on every refresh; the dispatch gate injects the windows into the plan turn; the ledger guard compares the plan estimate to the remaining allowance through a measured tokens-per-percent calibration and warns or blocks; dispatchwright gains the plan table, the confirmation stop, and the window-fit procedure with an ask-the-owner fallback.
- Owner steps at the end: the statusline setting (settings.json is protected) and the hook Copy-Item lines, delivered as finished files under handbook\config.
