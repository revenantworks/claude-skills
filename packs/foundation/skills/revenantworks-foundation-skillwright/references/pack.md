# Pack — foundation *(standalone profile)*

> Advisory only — consulted on boundary doubt; initial routing stays at the name + description level. **Last stamped: 2026-10-08** (nine-member roster + canonical repo; generated from the registry in skillwright's `pack-registry.md`).

**foundation seam notes:**

- **dispatchwright ↔ handoffwright** (added 2026-09-11, with the member's 1.0.0 build under its first name, resumewright; renamed 2026-09-28): the
  newest member and its nearest neighbor. Both sides carry the claim from the first commit that
  adds either — handoffwright's own description names the dispatchwright carve-out, and
  dispatchwright 1.2.5 adds a matching §1 bullet plus a one-sentence pointer from its own
  `resume` entry, so the row opens as **both descriptions** rather than the one-sided pattern the
  three original dispatchwright rows above started at.

- **dispatchwright ↔ {promptwright, rigwright, agentwright}** (added 2026-08-18): `build.py --check` flagged dispatchwright as "named in no routing seam" from its 1.0.0 release (2026-08-18) forward. The three edges are real and were never in doubt — dispatchwright's own SKILL.md §1 states them by quoting the sibling that owns the other half of each ("The tier table is promptwright's," "Where the trigger lives is rigwright's," "Unattended runs are agentwright's, whole") — but the rows were never added to this table, and the member's own README named the gap explicitly under "What did not land at 1.0.0" rather than leaving it silent. All three rows are now present above. Every edge is genuinely uncontested rather than negotiated: none of promptwright's, rigwright's, or agentwright's descriptions mention dispatchwright or fan-out dispatch by name, so nothing on their side claims the territory dispatchwright is ceding or taking — the split is dispatchwright unilaterally staying out of model-picking, hook-placement, and unattended scheduling, not a boundary either sibling had to give ground on. The signal column reads **one description** on all three for that reason, not as a mark against them: an uncontested edge stated on only one side is not the same failure mode as the evalwright ↔ skillwright row (retired 2026-10-08), where the claim was actively wrong. The warning `--check` prints is therefore now informative rather than a real gap — it should be read as "three declared, uncontested edges," and should stop firing once the three rows above are live in a build. **The promptwright row was dropped on 2026-09-28** (dispatchwright 1.4.0, parity run C3): dispatchwright has tiered from its own table (`references/tier-routing.md`) since 1.2.9, so it no longer hands units to promptwright or copies a table back, and the row described a seam that had stopped existing (observation #0078). The rigwright and agentwright rows stand.

- **dispatchwright ↔ pacewright** (added 2026-09-28, with pacewright's 1.0.0 split): the user split usage pacing out of dispatchwright 1.3.2. The seam is a data file, never a file load (observation #0189): pacewright is the one writer of `~/.dispatch/budget-decision.json` (schema version, `written_at`, `expires_at`); dispatchwright reads it when present and unexpired and otherwise runs its own small fallback fit, so each member stands alone. `references/window-fit.md` moved to pacewright whole, and the dispatchwright trigger rows about fitting a window moved with it; the boundary pair is dispatchwright's "fit these units into my window and show me the plan table" against pacewright's "how fast should I spend this week". Both descriptions name the other from the first commit, so the row opens as **both descriptions**. The cold re-judge of both suites is owed and disclosed in each member's `evals/RESULTS.md`.

- **pacewright ↔ agentwright** (widened 2026-09-28, D5, agentwright audit P2-9): routines are fixed-cost members of the week. agentwright owns a routine's cadence; pacewright's budget reads each routine's measured per-fire cost and reserves it before any other work is fitted. The data flows one way, as with the dispatchwright seam: pacewright reads what a routine cost, and never edits the routine or its schedule.

- **skillwright ↔ agentwright** (added 2026-07-27, pack 1.3.0): closed a boundary that shipped one pass earlier claimed from one side only. agentwright 1.2.0 and skillwright 1.4.0 each took a security capability and each wrote a reciprocal boundary sentence into its own `description`, but the row itself was deliberately skipped that pass because adding it regenerates all eight manifests — so the seam existed in routing metadata and nowhere the table could see it. Recorded plainly because it is the class of gap this table exists to catch: `tools/build.py`'s boundary-pair check validates the rows that are declared and has no way to notice one that is missing, so a `--check` clean run was never evidence the seam was covered. The deciding word is **injection**, now in two descriptions at once — the first time any single security token has been — which is why the row keys on the object rather than the vocabulary and why skillwright trigger rows #38-#43 pair each security query against its opposite-object twin (#42 against #38 is the sharpest, #43 sits outside both on purpose). Both sides carried the claim, so the signal read **both descriptions**; the cold re-run that would instrument it is owed and disclosed, not claimed. **Narrowed 2026-10-01 (owner Q3, pack split):** agentwright's runtime security scan moved to gatewarden (warden pack) as `scan`; agentwright keeps cadence, guardrail and kill-switch design and isolation of untrusted input (data, never instructions), and skillwright's description now hands runtime findings to gatewarden's scan, so the row reads **one description** (agentwright names skillwright) and the runtime half lives in the cross-pack row gatewarden ↔ skillwright.

- **`sanitize`** is object-decided: a skill set handed to a new owner is skillwright port, a brand identity swept across a tree is brandscribe's audit (scribe pack), a public-bound message is commscribe's (scribe pack), and a leak scan before publishing is shieldwarden's (warden pack).

- **Retired 2026-10-01 (owner O2, pack split):** brandwright, commwright and lorewright left the roster when the scribe pack landed; their seam rows here (skillwright ↔ lorewright, skillwright ↔ brandwright, commwright ↔ brandwright, promptwright ↔ lorewright, skillwright ↔ commwright) were removed. Successors live in the cross-pack table: researchscribe ↔ skillwright, researchscribe ↔ promptwright, brandscribe ↔ skillwright, commscribe ↔ skillwright. The prose split those rows carried still holds under the new names: a skill package's own files (SKILL.md, its README, references, a pack's CLAUDE.md) are skillwright's prose pass; docs prose for people and messages bound for a channel are commscribe's (owner Q20).

- **Retired 2026-10-08 (owner-approved consolidation, eleven → nine):** evalwright folded into skillwright as its `evals` entry and tokenwright retired into `slim` entries held by each owner (skillwright for a skill package, promptwright for a prompt, rigwright for standing config). Their rows here (promptwright ↔ tokenwright, evalwright ↔ skillwright, skillwright ↔ tokenwright, rigwright ↔ tokenwright) were removed, pacewright ↔ tokenwright was re-pointed to pacewright ↔ skillwright, and the rigwright ↔ skillwright and promptwright ↔ skillwright rows now carry the slim and evals splits. Across packs, godotsmith ↔ evalwright became godotsmith ↔ skillwright and commscribe ↔ tokenwright became commscribe ↔ promptwright. The slim split is by object, never by verb or motive; the motive only picks the mode inside the user. The notes those rows carried are in git history.

- **Naming notes:** "prose" appears in one foundation description (skillwright, for a skill package's own files) and "CLAUDE.md" in two — skillwright's, claimed for a pack's CLAUDE.md as package prose only; and rigwright's, claimed for placement and setup (the count read three from 2026-08-05 until tokenwright retired on 2026-10-08). rigwright's description also names AGENTS.md and path-scoped `.claude/rules` since P1c (2026-10-01); the CLAUDE.md count is unchanged. rigwright's description names `.claude/agents` since FX1 (J1 E1: a subagent roster is standing config, not prompt text).

- **README carries the prose seam** (opened and closed 2026-07-25; re-pointed 2026-10-01; moved 2026-10-04, owner decision on observation 0308 — an installed plugin never loads the pack's `CLAUDE.md`, so the router file was deleted): the "Which skill does what" section of `packs/foundation/README.md` holds it.
