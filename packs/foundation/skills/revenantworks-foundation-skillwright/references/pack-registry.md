# Pack Registry — structural single source of truth *(event-driven surface)*

## Contents

- Build defaults
- The pack registry
- Per pack: members, budgets, seams (foundation), capstone, canonical repo — foundation, then gamedev
- Cross-pack seams and the planned line
- Featured (one-skill plugins) and the featured line

> The canonical roster and pack structure `tools/build.py` derives every
> `references/pack.md` from. **Event-driven** — updated on roster or pack
> changes only, not on a calendar (no staleness stamp). Holds only what a
> *build* needs to name and stamp a member. Brand **styling** — palette, voice,
> taglines, wordmark — does **not** live here, and no member applies a brand:
> every member ships neutral (a brand definition is brandscribe's, scribe pack,
> and stays outside this repo). The token below is a **label** (it names skills
> and stamps frontmatter); it applies no styling on its own.

**foundation budgets** *(body-footprint table — one row per member; `build.py` validates each member's measured SKILL.md body against its row)*

Declared here rather than in each member's frontmatter, changed 2026-07-27. The gate is unchanged — a body's size must be **declared and justified**, per the item-③ rescope — but the justification is build-time data, and frontmatter is loaded on every single invocation of the skill. A `why` in `metadata.body_budget` cost 51–95 tokens per member *every time that member ran*, to explain a number no runtime reader ever acts on. That is the exact waste a slim exists to find, sitting in the pack's own gate. The registry is already `build.py`'s single source of truth, no member loads another member's registry, and nothing here ships in a member's zip — so a row costs zero runtime tokens. **That is what makes declaring all eight affordable**: eight frontmatter blocks would have cost ~400 tokens per session to say that five members have no size problem.

**Standalone skills built outside a pack keep a body budget in frontmatter** — they have no registry to declare into, so `build-templates.md` still teaches it, as two string keys (`body_budget`, `body_budget_why`), because the spec types every `metadata` value as a string (changed 2026-10-08). It is the pack-member case that moves.

**foundation seam notes:**

- **dispatchwright ↔ handoffwright** (added 2026-09-11, with the member's 1.0.0 build under its first name, resumewright; renamed 2026-09-28): the
  newest member and its nearest neighbor. Both sides carry the claim from the first commit that

  dispatchwright 1.2.5 adds a matching §1 bullet plus a one-sentence pointer from its own
  `resume` entry, so the row opens as **both descriptions** rather than the one-sided pattern the
  three original dispatchwright rows above started at.

- **dispatchwright ↔ {promptwright, rigwright, agentwright}** (added 2026-08-18): `build.py --check` flagged dispatchwright as "named in no routing seam" from its 1.0.0 release (2026-08-18) forward. The three edges are real and were never in doubt — dispatchwright's own SKILL.md §1 states them by quoting the sibling that owns the other half of each ("The tier table is promptwright's," "Where the trigger lives is rigwright's," "Unattended runs are agentwright's, whole") — but the rows were never added to this table, and the member's own README named the gap explicitly under "What did not land at 1.0.0" rather than leaving it silent. All three rows are now present above. Every edge is genuinely uncontested rather than negotiated: none of promptwright's, rigwright's, or agentwright's descriptions mention dispatchwright or fan-out dispatch by name, so nothing on their side claims the territory dispatchwright is ceding or taking — the split is dispatchwright unilaterally staying out of model-picking, hook-placement, and unattended scheduling, not a boundary either sibling had to give ground on. The signal column reads **one description** on all three for that reason, not as a mark against them: an uncontested edge stated on only one side is not the same failure mode as the evalwright ↔ skillwright row (retired 2026-10-08), where the claim was actively wrong. The warning `--check` prints is therefore now informative rather than a real gap — it should be read as "three declared, uncontested edges," and should stop firing once the three rows above are live in a build. **The promptwright row was dropped on 2026-09-28** (dispatchwright 1.4.0, parity run C3): dispatchwright has tiered from its own table (`references/tier-routing.md`) since 1.2.9, so it no longer hands units to promptwright or copies a table back, and the row described a seam that had stopped existing (observation #0078). The rigwright and agentwright rows stand.

- **dispatchwright ↔ pacewright** (added 2026-09-28, with pacewright's 1.0.0 split): the user split usage pacing out of dispatchwright 1.3.2. ## Featured

A featured member also ships alone, as a one-skill plugin in `featured/<skill>/` with its own `.claude-plugin/plugin.json` and marketplace entry. The rule (owner decision 5, pacewright first): a member is featured when it is unique among public incumbents — a parity verdict with a named margin nobody else has — runs with no sibling installed, and has passing evals. `build.py` generates the plugin from the pack source: the skill folder copied file for file, the plugin version equal to the member version, and a landing-page `README.md` stub written once and then owned by hand. `--check` fails on any drift between the pack source and the featured copy, on a featured folder or marketplace entry this line does not name, and on a name that is not a registered member.
